# 系统权限申请政策与流程

## 症状 / 适用场景
- 新入职或转岗后缺少某些系统的访问权限
- 需要申请数据库、监控面板、内部工具等系统的账号或权限
- 承包商/外包人员需要临时访问权限

## 权限矩阵（Agent 可直接处理的范围）
1. 普通员工（employee）申请其岗位标准软件授权（如 Jira、Confluence、Grafana 只读）：Agent 核验身份后可直接授予
2. 普通员工申请本部门常用业务系统的只读权限：Agent 可直接授予
3. 数据库生产环境权限（如 Snowflake production）、admin 权限：Agent 无权授予，必须人工审批
4. 承包商（contractor）/外包人员的一切权限申请：必须由其担保经理审批，Agent 只创建申请工单
5. 高管（executive）相关的一切权限变更：转人工处理

## 解决步骤（Agent 可处理的情形）
1. 核验身份：employee_id + 部门信息
2. 查询员工目录确认角色与已有权限（entitlements）
3. 用 check_policy 确认该权限属于"标准软件授权"范围
4. 执行 grant_standard_software 并告知生效时间（约 5 分钟同步）

## 何时升级人工
- 生产数据库权限：数据安全红线，一律人工审批
- 承包商权限：需要经理审批流，Agent 创建工单并注明担保人
- 申请范围与岗位不符（如市场部申请财务生产库）：转人工审查，可能涉及合规问题
